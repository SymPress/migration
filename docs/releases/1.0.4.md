# Release 1.0.4

Forward and rollback SQL plans are resolved after the WordPress executor acquires
the database advisory lock. Applied state is rechecked before planning; SQL is
classified for transactional execution only after the live plan is available.
Planning exceptions release the lock and leave migration state/history unchanged.

The additive `DeferredMigrationOperationExecutor` contract exposes this boundary
to custom executors. Existing `MigrationOperationExecutor` and
`MigrationSqlExecutor` implementations remain compatible with their prior
semantics. Stable keys, registration order, SQL routing, DML transactions and
irreversible rollback safeguards are preserved.

Local PHP 8.5 verification passed: `composer qa` (65 tests, 444 assertions) and
`composer tests:database` (6 tests, 77 assertions) against a fresh disposable
MariaDB schema. Hosted release verification and registry publication are separate
delivery steps.
